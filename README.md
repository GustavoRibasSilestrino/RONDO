# RONDO

Compita com quem você foi ontem.

App de treino, dieta, constância e comunidade, com recados de voz para o seu "eu do futuro" e profissionais verificados.
Este arquivo é a documentação geral: leia do começo ao fim para continuar o trabalho em outra máquina.

- **App (versão web):** https://userondo.vercel.app/app (o endereço antigo, rondo-app-eight.vercel.app, redireciona para ele)
- **Site:** https://userondo.vercel.app
- **API:** https://rondo-api-mt29.onrender.com (saúde em `/saude`)
- **Repositório:** https://github.com/GustavoRibasSilestrino/RONDO (branch `main`)

## 1. Visão geral

Três projetos na mesma pasta, cada um com o seu `package.json` ou `requirements.txt`:

| Pasta | O que é | Tecnologia | Onde roda |
|---|---|---|---|
| `app/` | O app (celular e web) | Expo 58, React Native 0.88, react-native-web, TypeScript | Vercel (versão web) e Expo (celular) |
| `backend/` | A API | FastAPI, SQLAlchemy, Alembic, Postgres | Render |
| `vitrine/` | O site de divulgação, cadastro de profissionais e páginas legais | Vite, React 19 | Vercel |

Outras pastas: `brand/` (símbolo da marca e o RONDIN em 3D, ver seção 6), `docs/` (conformidade e fichas das lojas), `site/` (versão antiga do site, não é a publicada),
`PRODUCT.md` (público e posicionamento do produto).

Fluxo de publicação: **push na `main` dispara tudo**. A Vercel publica o site e o app web; o Render publica a API e roda `alembic upgrade head`
antes de subir. Desde 2026-11-07 o dono autorizou **commitar e dar push direto na `main`, sem perguntar** (ver seção 8); migrações rodam sozinhas no deploy, então **avise quando houver migração nova**.

```
 app (Expo/web) ──┐                      ┌── Supabase Postgres (dados)
                  ├──►  API FastAPI ─────┤
 vitrine (site) ──┘     (Render)          └── Supabase Storage (fotos, bucket "midia")
```

## 2. Continuar em outra máquina (passo a passo)

Precisa de: Git, Node 20+ (testado com 24), Python 3.12 e, para o app no celular, o Expo Go.

```bash
git clone https://github.com/GustavoRibasSilestrino/RONDO.git
cd RONDO
```

**API local** (sem `DATABASE_URL` usa SQLite; nunca toca no banco de produção):

```bash
cd backend
python -m venv .venv
.venv/Scripts/pip install -r requirements-dev.txt     # Linux/Mac: .venv/bin/pip
cp .env.example .env                                  # deixe DATABASE_URL vazio para usar SQLite
.venv/Scripts/alembic upgrade head
.venv/Scripts/uvicorn app.main:app --reload --port 8123
.venv/Scripts/python -m pytest -q                     # 82 testes devem passar
```

**App:**

```bash
cd app
npm install
echo "EXPO_PUBLIC_API_URL=http://localhost:8123" > .env.local
npm run web          # abre no navegador; npm start para o celular (Expo Go)
npm run typecheck
```

**Site:**

```bash
cd vitrine
npm install
npm run dev          # http://localhost:5173
npm run build        # roda tsc e o vite build; saída em dist/
```

Arquivos que **não estão no Git** e precisam ser recriados na outra máquina: `backend/.env`, `app/.env.local`, `app/.env.production`,
`vitrine/.env.production`. As chaves reais ficam só nos painéis do Render e do Supabase. **Nunca cole chaves no chat nem no repositório.**
Na raiz há arquivos de ferramenta que não são do produto e não vão no commit: `.claude/`, `.impeccable/`, `.mcp.json`,
`PRODUCT.md`, `vitrine/app-preview.html`.

## 3. Variáveis de ambiente

**API (`backend/.env` local; painel do Render em produção):**

| Variável | Para quê |
|---|---|
| `DATABASE_URL` | Postgres. Em produção use o **pooler do Supabase em modo transação, porta 6543**, com prefixo `postgresql+psycopg://`. Sem ela, usa SQLite local |
| `JWT_SEGREDO` | Segredo longo (32+ caracteres) que assina o login. Diferente em produção |
| `ORIGENS_PERMITIDAS` | Domínios que podem chamar a API (CORS), separados por vírgula |
| `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `SUPABASE_BUCKET` | Fotos e vídeos dos posts e stories (bucket `midia`). A chave é a `service_role`, só no servidor |
| `AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION` | Voz do RONDIN para nomes e números. Opcional |
| `BREVO_API_KEY` (ou `RESEND_API_KEY`), `EMAIL_REMETENTE`, `EMAIL_REMETENTE_NOME` | E-mail da recuperação de senha, por API HTTP (o plano grátis do Render bloqueia SMTP). Sem elas o código não é enviado. `EMAIL_MODO_TESTE=true` escreve o e-mail no log, só em desenvolvimento |
| `GOOGLE_CLIENT_IDS`, `APPLE_CLIENT_IDS` | IDs de cliente para entrar com Google e Apple (separados por vírgula). Sem elas, as rotas respondem 503 |
| `DB_POOL_TAMANHO`, `DB_POOL_EXTRA`, `MAX_PEDIDOS_SIMULTANEOS`, `LIMITE_REQ_MINUTO`, `LIMITE_AUTH_MINUTO` | Ajustes de escala (padrões em `backend/app/config.py`; 0 desliga o limite) |

**App:** `EXPO_PUBLIC_API_URL`, a URL da API; `EXPO_PUBLIC_GOOGLE_CLIENT_ID` e `EXPO_PUBLIC_APPLE_CLIENT_ID` ligam os botões de login social (só aparecem com elas). **Site:** `VITE_API_URL`, a mesma URL.
Passo a passo da Brevo, do Google e da Apple em `docs/login-social.md`.

## 4. App (`app/`)

- **Entrada:** `App.tsx` (Login ou telas; menu lateral no computador, barra de abas no celular). `index.ts` registra o app.
- **Telas** (`src/telas/`): Início, Hoje, Treino, Dieta, Evolução, Comunidade e Feed (`Social.tsx` e `comunidade/`), Recado de voz, Coleções, Notificações, Perfil (`perfil/`), busca de profissionais e, para quem não está logado, Login, Início (só no celular), Rondin (a conversa de entrar e criar conta) e Esqueci a senha.
- **Estado:** `src/estado/loja.tsx`. Guarda no aparelho (AsyncStorage) e **sincroniza com o servidor por chave** na tabela `dados_usuario` (`src/api/sincronia.ts`; as chaves aceitas estão em `backend/app/rotas/me.py`). Ao entrar, puxa os dados da conta.
- **API do app** (`src/api/`): `cliente.ts` (fetch com token), `sessao.ts` (token no `expo-secure-store`), `conta.ts`, `social.ts`, `seguranca.ts`, `privacidade.ts`, `sincronia.ts`.
- **Lógica** (`src/lib/`): cálculos (`calc.ts`, 1RM de Epley), nível e XP (`nivel.ts`, `patentes.ts`), medalhas, rotinas de treino, importar treino, stories, notificações, o Rondin (`rondinRoteiro.ts`, `rondinTextos.ts`, `rondinSotaques.ts`, `rondinVoz.ts`), como a pessoa chegou (`entrada.ts`), largura (`largura.ts`).
- **Componentes** (`src/componentes/`): menu lateral e painel de gráficos (só no computador), `BotaoMais` (o +), fundo com foto das telas de dentro (`FundoCena.tsx`), o fundo preto animado do Rondin (`FundoRondin.web.tsx` no navegador, `FundoRondin.tsx` no celular), a abertura do app do celular (`Abertura.tsx`), o orbe do Rondin (`Orbe.web.tsx` no navegador, `Orbe.tsx` no celular), gráficos (`Grafico.tsx`), stories, medalhas 3D, a chama da sequência (`ChamaJoia.tsx` e `SeloSequencia.tsx`). `FundoBolhas.tsx` (as bolas roxas do fundo antigo) ficou no projeto, mas não é mais usado.
- **Layout:** celular usa barra de abas embaixo. Janela web a partir de **1024 px** ganha menu lateral (com hambúrguer para recolher); a partir de **1240 px** ganha a coluna da direita com os gráficos de Evolução e Constância. O + fica na borda direita da área.
- **Tema:** `src/tema.ts`. Uma aparência só: preto com roxo, redondo, Poppins fina, e uma foto de paisagem no fundo de cada tela de dentro (ver "Fotos de fundo" abaixo); as telas do Rondin são pretas, com animação. Não há troca de tema (o tema Ultra e a transição ULTRA foram removidos em 2026-11-10, para o app ficar mais original); `cores` é a paleta única e `estilos(...)` calcula os estilos uma vez.
- **Fotos de fundo** (`componentes/FundoCena.tsx`, imagens em `assets/cenas/`): cada aba tem uma foto, que nasce do preto (degradê cheio do preto no alto e embaixo, meia força no meio): Feed `picos-noite`, Treino `serra-dia`, Comunidade `vale-nuvens`, Dieta `serra-dia`, Perfil `serra-noite` (a lista está em `DA_TELA`). As bolas roxas do fundo antigo saíram. As telas do Rondin não usam foto; `assets/cenas/rondo-montanhas.webp` (a serra com o nome RONDO) ficou no projeto, mas o app não a usa mais.
- **Botões** (`Botao`, em `componentes/Ui.tsx`, desde 2026-11-12 pela referência em vídeo do dono): todos em **pílula** e todos com o mesmo efeito. **Parados ficam apagados** (pílula cinza escura, texto acinzentado; o de perigo com o texto vermelho) e **acendem quando o cursor chega**, no momento antes do clique: crescem um pouco, o texto fica branco, um brilho passeia na parte de baixo (`BrilhoAndante`) e uma luz se espalha em volta; tirando o cursor, apagam devagar (0,65 s). Violeta (`#9168ff` a `#6639f4`) em todos, menos o de **perigo**, que acende em **vermelho**. O foco do teclado também acende. Onde não há cursor (celular, tablet), o principal fica sempre aceso e os outros acendem ao toque. Sem estrelinhas nem brilhos "de IA".
- **Sequência:** a regra está em `src/lib/calc.ts` (`streakAtual`: dias seguidos com treino, 2 refeições ou check-in; uma falta por semana não quebra; `diasDaSequencia` devolve os dias que contam; `situacaoDaSequencia` diz se a chama está acesa, em risco ou apagada). O desenho é uma **chama roxa plana (2D), sem contorno** (`ChamaJoia.tsx`, vetorial: duas formas chapadas, a chama e o miolo mais claro; a versão em joia lapidada saiu em 2026-11-10, o nome do arquivo ficou): acesa quando já houve registro hoje, mais fraca quando a sequência vive mas hoje ainda não teve registro, cinza quando não há sequência. O `SeloSequencia` (chama + número de dias, sem fundo e sem borda) fica no **canto de cima, à esquerda**, em todas as telas (no cabeçalho no celular, antes das notificações; no canto da área no computador) e abre o calendário. No canto de cima à direita fica só a lupa da busca. No celular o nome RONDO do meio do cabeçalho se ajusta ao espaço: no centro em 390 px ou mais, menor e deslocado para o vão livre em telas mais estreitas (`CabecalhoApp.tsx`). A chama também marca os dias da sequência no calendário (`CalendarioMes.tsx`) e aparece em Hoje, Evolução, no painel lateral e onde o ícone `chama` já existia (o `Icone` de nome `chama` desenha a mesma chama).
- **Popups de baixo (`Folha`, em `Estrutura.tsx`):** fecham arrastando a alça ou o título para baixo, ou tocando na alça; no celular, de qualquer ponto com o conteúdo no topo.
- **Conta:** entrar e criar conta só pelo Rondin (ver "Entrada" e "Rondin" abaixo); **esqueci a senha** com código de 6 números por e-mail (`telas/RecuperarSenha.tsx`, na língua escolhida no Rondin); **entrar com Google e Apple** só no navegador por enquanto (`componentes/BotoesSociais.tsx`, `telas/CadastroSocial.tsx`, `lib/loginSocial.ts`); **nome de conta único** (conferido já no cadastro). O app acorda o servidor ao abrir (`aquecerApi`), porque o plano grátis do Render dorme.
- **Perfis e stories:** a foto de perfil vem do servidor (aparece em todos os aparelhos e para os outros); o perfil de outra pessoa mostra clubes, seguidores e quem ela segue (a lista abre o perfil, com pilha de voltar); os stories têm reação (um emoji no canto de baixo à direita que abre as outras para cima), curtir e a lista de quem viu (bolinhas no canto de baixo à esquerda, `+N` quando passa de 3); a lupa de busca (nome sem acento, erro de digitação perdoado, quem você segue primeiro) fica sozinha no canto direito do cabeçalho, e no canto de cima à direita do feed no computador.
- **Política de conteúdo (desde 2026-11-12, `backend/app/servicos/penalidades.py`):** palavras ofensivas são **bloqueadas** antes de publicar (`servicos/filtro.py`, lista em `servicos/palavras_bloqueadas.py`, em português, inglês e espanhol; pega truques como `p.u.t.a`, `pu7a`, letras repetidas e palavras grudadas, e não barra palavras inocentes como "curso" ou "a bola rola"). Vale para posts, comentários, stories, clubes, nome, @ e bio; no cadastro, nome ofensivo é só recusado. Cada tentativa barrada é um **aviso**; conteúdo tirado do ar pela moderação também. **3 avisos**; passou do limite (a 4ª vez), **suspensão de 7 dias** (usa o app, mas não publica) e os avisos zeram. Depois da **2ª suspensão**, a próxima violação já **bane** (sem novo ciclo de avisos): nenhum pedido passa, o login é recusado e o app sai da conta com o aviso. Histórico na tabela `penalidades` (entra na cópia dos dados e sai ao apagar a conta). No app, Configurações > Comunidade e segurança mostra "Avisos: X de 3 · Suspensões: Y de 2" e até quando a conta está suspensa. Os números ficam em `LIMITE_AVISOS`, `SUSPENSOES_ATE_BANIR` e `DURACAO_SUSPENSAO`. Está nos Termos de Uso (seção 4).
- **Plano PRO:** a estrela roxa fica só no **Perfil** (primeiro botão da barra de cima, abre `PlanoPro`); saiu do cabeçalho e do menu lateral. O botão "Ver os planos no site" e o preço aparecem **só no navegador**: no app instalado (`PlanoPro.tsx` e `AvisoPro` em `Pro.tsx`) não há link nem preço, porque a App Store e o Google Play recusam app que manda pagar fora da loja. Quando o PRO for vendido, no celular terá de ser pela compra dentro do app.
- **Segurança da comunidade (exigência das lojas):** toda publicação, comentário, story e perfil de outra pessoa tem os **três pontinhos** com **Denunciar** (motivo e detalhe opcional) e **Bloquear** (`componentes/Denunciar.tsx`). O que a pessoa denunciou some só para ela. O bloqueio vale nos dois sentidos: deixam de se seguir e nenhum vê mais posts, comentários, stories, perfil ou busca do outro, nem recebe aviso dele. Em Configurações: **Comunidade e segurança** (regras, pessoas bloqueadas com Desbloquear, contato da equipe) e, só para o dono, **Denúncias** (`telas/perfil/Comunidade.tsx`): a fila com o trecho e a foto denunciados, Manter ou Tirar do ar (em perfil, Remover a conta). Cada denúncia nova manda e-mail para o dono quando o e-mail estiver configurado (Brevo). Os Termos (seção 4) dizem que há tolerância zero e que as denúncias são analisadas em até 24 horas: **é preciso olhar a fila todo dia**.
- **Análise da execução (câmera):** botão de câmera à esquerda do título em **Treino**. Primeiro o RONDIN pergunta (texto e voz) qual exercício a pessoa vai fazer; ela digita (`exercicioDoTexto` em `src/lib/postura.ts` reconhece agachamento, flexão, rosca, desenvolvimento e prancha, com sinônimos; se não reconhecer, o RONDIN diz quais sabe corrigir) e a câmera abre já configurada para ele. Só aí o aparelho pede a permissão da câmera. O detector de pose é o MediaPipe Pose Landmarker (`@mediapipe/tasks-vision@1.1.1`, carregado do jsDelivr com SRI; modelo `pose_landmarker_lite` do Google Storage) e roda **no aparelho**: o vídeo não é gravado nem enviado. O `Analisador` (em `postura.ts`) mede os ângulos das articulações, conta repetições e certas e gera as correções ("Cotovelo mais para frente, junto ao corpo", "Desça mais: quadril na altura do joelho"...); a tela (`componentes/AnaliseExecucao.web.tsx`) desenha o esqueleto, um anel vermelho no ponto a corrigir, a seta até onde ele deve ir e o texto, e fala a correção em voz alta (dá para desligar). **No app instalado** (`AnaliseExecucao.tsx`) o toque pede a permissão da câmera do celular (`expo-image-picker`; `CAMERA` no Android em `app.json`) e abre em tela cheia um WebView (`react-native-webview`) com `/app/?camera=1`, a mesma análise sozinha; o X da página avisa o app para fechar. Por isso a análise no app depende do site publicado. A CSP (Report-Only, `app/vercel.json`) libera `cdn.jsdelivr.net`, `storage.googleapis.com`, `wasm-unsafe-eval` e `mediastream:`.
- **Treino em casa:** `src/lib/semAparelho.ts` tem 22 exercícios sem aparelho e 4 treinos prontos, no editor de treino (Criar treino > Treino para fazer em casa).
- **Social:** feed estilo Instagram, stories, curtidas ("cheers"), comentários, seguir, clubes, ranking semanal, notificações, pergunta do dia. Fotos sobem para o Supabase Storage e o post guarda a URL.
- **Abertura e chegada (desde 2026-11-13):** toda vez que o app abre, no celular e no navegador, a primeira coisa é a **tela preta com o nome RONDO** (no navegador, a tela de carregamento de `public/index.html` e a `Abertura` têm o mesmo nome no mesmo lugar, sem piscar; o relógio dela está em `lib/abertura.ts` e as telas do RONDIN esperam por ele, `atrasoDaAbertura()`); **depois vem o RONDIN**. Quem não está logado vê a apresentação e a conversa de entrar; quem está logado vê a **chegada** (`componentes/Chegada.tsx`, por cima do app): na primeira abertura do dia, e logo depois de criar a conta, ele já **faz a pergunta do dia** (a tela do recado, abaixo); "Agora não" leva direto ao app e marca o dia (`yy.chegada.v1` no aparelho). Nas outras aberturas do dia (já respondeu ou já disse "agora não") ele só **cumprimenta** ("Bom dia, Ana. Bom te ver.") e deixa entrar sozinho depois da fala, ou ao toque.
- **Recado de voz com o RONDIN (desde 2026-11-13):** o antigo recado era uma tela de gravação; agora é uma **conversa** (`telas/Recado.tsx`, que usa `componentes/CenaRondin.tsx`: o mesmo orbe, fundo e legenda do cadastro). Ele faz a **pergunta do dia**, a pessoa responde em voz alta (até 1 minuto, onda ao vivo), ele reage e faz a **segunda pergunta**, a pessoa responde de novo e ele encerra. **Dá para não responder** ("Agora não") e, ao fim, **guardar no diário ou descartar**; sair com respostas por guardar pergunta antes (também no botão voltar do Android, `lib/interceptarVoltar.ts`). Plano grátis: uma conversa guardada por dia ("Hoje nós já conversamos..."); PRO: sem limite. As **perguntas** (`lib/perguntas.ts`, 14, uma por dia, a mesma para todos, em pt/en/es, cada uma com a segunda pergunta) são de filosofia, feitas para pensar. A conversa (`lib/rondinConversa.ts`) **não usa IA**: é um roteiro com reações gerais; com a transcrição (só no navegador e só com a voz ligada, abaixo) ele repete uma palavra que a pessoa disse e percebe se o tom foi leve ou pesado. A língua é a que a pessoa escolheu no cadastro. Cada resposta vira um `Recado` com `grupo` (a conversa) e `turno` (1 ou 2); os de antes, sem `grupo`, valem como conversa de uma resposta. Novos recados chegam na hora (`entrega` = hoje); os antigos, trancados até uma data, continuam trancados. **Diário de recados** (`telas/Diario.tsx`, botão no Perfil, no canto da tela do recado e na chegada): calendário (`componentes/CalendarioRecados.tsx`) com os dias em que a pessoa gravou, tocar num dia mostra os áudios dele, e embaixo **todos os áudios**, por dia, para ouvir ou apagar; também mora ali o "Seu ano em áudio" e "Apagar todos". **Onde o áudio fica** (`lib/audioGuardado.ts`): no celular, copiado para a pasta de documentos do app ao guardar (a gravação nasce no cache); no navegador, no **IndexedDB** do navegador (o endereço `blob:` morre ao recarregar). Só no aparelho: o servidor guarda a lista (pergunta, duração, datas, `grupo`, `turno`), nunca o áudio. Testes das partes puras: `npm run testar:rondin`.
- **"Olá Rondin" (desde 2026-11-13, só no navegador):** `lib/escuta.ts` + `lib/chamado.ts` + `componentes/RondinChamado.tsx`. Com a escuta ligada, dizer "Olá Rondin" (ou "hello", "hola", "bonjour", "ciao"...; o nome é comparado de forma aproximada, e a frase precisa ter uma saudação ou ser curta) faz o RONDIN aparecer por cima do app, **na língua da saudação**, com três botões (falar o recado do dia, abrir o diário, fechar). Usa o `SpeechRecognition` do navegador, uma língua por vez: a da pessoa de duas em duas rodadas e, entre elas, en, pt, es, fr, it e de. **Desligada por padrão:** o convite vem uma vez, na primeira cumprimentação, e o botão fica em Configurações > RONDIN pela voz (`telas/perfil/VozDoRondin.tsx`); o microfone só é pedido quando a pessoa liga. A escuta pausa sozinha enquanto o RONDIN fala ou a pessoa grava, e com a aba escondida; sem permissão, desliga e não insiste. No Chrome o áudio vai ao serviço de voz do Google; o RONDO não grava nem guarda nada disso (a Política de Privacidade diz isso). **No app do celular não existe:** precisaria de um módulo nativo (`expo-speech-recognition`) e de um novo build.
- **Entrada (quem não está logado), `telas/Login.tsx`:** **No navegador** não há tela inicial: a pessoa já escolheu no site. Os botões do site levam a `/app?conta=criar` ou `/app?conta=entrar` (lido uma vez em `lib/entrada.ts`) e a conversa com o Rondin abre direto nesse modo; abrir `/app` sem o pedido cai em "entrar"; a seta da primeira pergunta volta ao site; os botões do Google e da Apple e o link "Ainda não tenho conta" ficam junto dos campos de entrada. **No app do celular** a tela inicial (`telas/Inicio.tsx`: o orbe, "Criar conta" e "Já tenho conta") usa o mesmo fundo preto animado da conversa, com o cartão no centro da tela.
- **Tela de carregamento do navegador (`app/public/index.html`, gerada por `node --experimental-strip-types scripts/gerar-carregando.mjs`):** a página já nasce **preta, com o nome RONDO em branco no meio**, igual à abertura do app (até 2026-11-12 era o RONDIN no meio; desde 2026-11-13 é o nome, para toda entrada começar por "tela preta escrito RONDO" e só depois o RONDIN; sem script, por causa da política de conteúdo). Antes aparecia uma tela branca (o navegador esperando o app) e depois uma preta (o app esperando as fontes). Quando a primeira tela do app está pronta, `tirarCarregando()` (`src/lib/carregando.ts`, chamada no `App.tsx`) a apaga esmaecendo, e a `Abertura`, com o mesmo nome, assume no lugar. Rode o script de novo se mudar a abertura.
- **Apresentação do RONDIN (`telas/Apresentacao.tsx`, desde 2026-11-12):** a primeira tela antes de entrar ou criar conta. No celular, logo depois da abertura preta com o nome RONDO; no navegador, quando a pessoa chega do site pelos botões "Entrar" ou "Criar conta". ### Escala (muitos usuários ao mesmo tempo)

- Pool de conexões com limite (8 + 6), espera de 10 s e reciclagem a cada 280 s (`banco.py`). Na porta 6543 o código desliga comandos preparados.
- **Fila de pedidos:** no máximo 32 em andamento; o resto espera até 10 s e recebe 503 (`concorrencia.py`). Isso corrigiu um travamento em que as threads esperavam conexão e as conexões esperavam thread.
- **Limite por endereço:** 600 pedidos por minuto e 20 por minuto em login e cadastro; responde 429 (`limite.py`).
- Compressão gzip e índices nas tabelas sociais.
- Teste de carga: `node backend/scripts/teste_de_carga.mjs http://localhost:8123 400` (deve dar 400 respostas 200). **Só contra banco de teste.** Com SQLite novo, rode `alembic upgrade head` antes.

### Segurança (revisão de 2026-11-10, pelos 19 pontos, e de 2026-11-11)

Nenhum sistema é impossível de invadir; o que existe é fechar as portas conhecidas e manter a casa em ordem. Estado de cada ponto:

| # | Ponto | Situação |
|---|---|---|
| 1 | `.env` exposta | Nenhuma `.env` com segredo no repositório nem no histórico. Os `.env.production` versionados só têm o endereço público da API. Segredos ficam no painel do Render. |
| 2, 3 | Validação só no frontend / no backend | Toda entrada é conferida de novo na API (Pydantic, com tamanhos máximos). O que o app valida é só para avisar mais cedo. |
| 4 | SQL injection | Só SQLAlchemy com parâmetros; não há SQL montado com texto. |
| 5 | Autenticação fraca | Senha nova com 8 ou mais caracteres (antes 6). A API **não sobe em produção** com o `JWT_SEGREDO` padrão. `/docs` e `/openapi.json` ficam fechados em produção. |
| 6 | IDOR | Cada rota confere o dono (post, comentário, story, clube, foto de perfil só da pasta da própria pessoa). |
| 7 | Senhas direto no banco | Argon2id; o código de redefinição também é guardado só como hash. |
| 8 | Força bruta | Limite por endereço (20 por minuto nas rotas de entrada) **e trava por conta**: 8 senhas erradas em 15 minutos travam a conta por esse tempo, venha o pedido de onde vier (`app/protecao.py`). Código de redefinição: 5 tentativas e 3 códigos por hora. |
| 9 | Envio duplo | Os botões de enviar ficam desligados enquanto o pedido está no ar (site e app). |
| 10 | CSRF | Não há cookie de sessão: o login vai no cabeçalho `Authorization`, que um site de fora não consegue mandar. |
| 11 | Upload sem validação | Só extensões de imagem e vídeo, em pasta própria de cada pessoa, com endereço assinado de uso único; a chave do Storage nunca sai do servidor. **Falta:** o limite de tamanho e o tipo real do arquivo são do bucket no Supabase (conferir no painel). |
| 12 | Erros revelando informação | Erros de validação não devolvem o que foi enviado; login e "esqueci a senha" respondem igual exista a conta ou não. |
| 13 | Dependências vulneráveis | Site: 0 (`npm audit`). API: 0 (`pip-audit`, versões fixas). App: as que sobram são moderadas, todas em ferramenta de build do Expo (não vão para o aparelho; o conserto exige trocar a versão do Expo). API: versões atuais; `requirements.txt` não fixa versões. |
| 14 | Tokens | O token traz a marca da senha: **trocar ou redefinir a senha derruba todos os tokens antigos** (o aparelho que trocou recebe um novo). O token do login social não serve para entrar. Validade de 7 dias. |
| 15 | Rate limit | Por endereço em tudo (600 por minuto) e menor nas rotas de entrada. O endereço agora vem do cabeçalho do proxy (`CF-Connecting-IP`), não do `X-Forwarded-For`, que o visitante podia inventar para furar o limite. |

| 17 | SSRF | O servidor só chama endereços fixos (Google, Apple, Azure, Supabase, Brevo); nenhum endereço vem de quem usa. |
| 18 | Cookies inseguros | Não há cookies. |
| 19 | CORS | Só as origens do RONDO, só os métodos e cabeçalhos usados, sem credenciais. |

**Revisão de 2026-11-11 (o que foi achado e corrigido):**
- **Foto de outra pessoa pelo endereço:** a API aceitava qualquer endereço que começasse com `.../<seu id>/`, então `.../<seu id>/../<outro id>/foto.jpg` passava (mostrar ou pedir para apagar o arquivo de outra pessoa). Agora só vale o formato exato que a própria API gera, `<id>/<32 hex>.<ext>` (`url_da_pessoa` em `app/servicos/midia.py`), nos posts, stories e foto de perfil, e o apagar do Storage também só aceita esse formato.
- **"Esqueci a senha" entregava quem tem conta pelo tempo:** a resposta demorava mais quando a conta existia (o e-mail saía antes de responder). Agora o e-mail sai depois da resposta, em segundo plano.
- **Código de convite de clube:** dava para testar códigos sem limite próprio. Agora 8 códigos errados travam a pessoa por 15 minutos. E entrar num clube privado pelo número respondia 403 (confirmava que existia); agora é 404, como um clube que não existe.
- **`/assinaturas` aberta:** qualquer um criava pedidos anônimos. Agora exige login.
- **Versões do Python fixas** em `backend/requirements.txt` (antes o deploy pegava a última de cada uma). `pip-audit`: nenhuma falha conhecida nas dependências do servidor. `npm audit fix` no app corrigiu o `node-forge`.
- **CSP do app web ligada de vez** (ver abaixo). Nenhum segredo no histórico do Git (busca por chaves, tokens e senhas de banco).

Além disso: cabeçalhos de segurança em toda resposta da API (`Blindagem`, em `app/protecao.py`: `nosniff`, `X-Frame-Options`, HSTS, CSP) e corpo de pedido limitado a 8 MB; no site (`vitrine/vercel.json`), política de conteúdo (CSP) que só deixa rodar código do próprio site, HSTS e proibição de abrir em moldura; no app web (`app/vercel.json`), os mesmos cabeçalhos, com a **CSP ligada de vez desde 2026-11-11** (antes era só relatório). Ela foi testada com a build de produção servida com a política ligada: entrada do Rondin, abas, perfil, configurações e a câmera (o detector do jsDelivr e o modelo do Google) sem nenhum bloqueio. O login do Google e da Apple ainda não foi testado com ela, porque os IDs ainda não existem: quando forem ligados, conferir no console do navegador se aparece "Refused to". Testes: `backend/tests/test_seguranca.py`.

**Atenção no deploy:** confira no painel do Render que `JWT_SEGREDO` está definido com um valor longo e aleatório. Se estiver vazio, o deploy novo falha de propósito (a versão anterior continua no ar).
